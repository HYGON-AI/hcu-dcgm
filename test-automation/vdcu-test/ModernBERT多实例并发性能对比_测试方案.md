# 「ModernBERT 多实例并发性能对比（stream vs vDCU 隔离）」测试方案（总结版）

依据：《vDCU 虚拟化测试方案_v1.2_20261102》5.2 ModernBERT 模型微调十场景（TRN-001～010）、《vDCU 容器挂载测试》多容器场景、《HCU Device Plugin-v3.0.1》第 4 章 HCU-Device-Plugin 与 5.1 HAMi，及组长对十场景实现方法的新要求（2026-11 会议纪要）。

## 1. 背景与现状

1. **十场景现状**：TRN-001～010 均已通过，但多实例场景（TRN-006～010）的关键数据不完整——TRN-009/010 仅记录"补跑数据见套件日志"，且未给出"整卡多实例（stream）与 vDCU 隔离多实例"的直接对比结论。
2. **组长明确测试目的**：多实例场景要回答的核心问题是——**同卡并发下，"多 stream 共享整卡"与"vDCU 隔离（等分 / CU 共享等分）"两种机制的单实例性能差异**。
3. **受限根因**：十场景及相关 K8S/HAMI 用例的「受限」由 HAMi 模式环境导致；今后使用 HAMi 模式必须按《HCU Device Plugin-v3.0.1》第 4 章与 5.1 节的方案部署。

## 2. 组长要求提炼（对话 → 验证要求）

1. **两种并发机制对照**：
   - 整卡起 2/4 个实例 = **多 stream 操作**：两个任务以两个流共享整卡（无隔离）；
   - 二等分/四等分（含 CU 共享）= **vDCU 隔离**：两个虚拟卡、两个进程各自运行；
   - 对比两者**每个单实例的性能**，找出差异点。
2. **测量纪律**：测性能时必须把 2 个或 4 个**相同实例全部拉起、全部处于运行状态**后再比较，不能出现"先测完一个再测下一个"的串行测量。
3. **预期结论**（依据建强文档）：**stream 多实例与 CU 共享四等分应无明显差异**——测试应验证该结论并量化差异。
4. **HAMi 部署约束**：受限问题源于 HAMi 模式，以后 HAMi 模式必须按官方文档部署（详见第 6 节）。

## 3. 对比矩阵与指标

| 对比组 | 机制 | 预期关系 |
| --- | --- | --- |
| TRN-006 整卡 2/4 实例 | 多 stream 共享整卡（无隔离） | 基线组 |
| TRN-007/008 等分 2/4 实例 | vDCU CU+显存隔离 | 单实例吞吐 ≈ 整卡单实例 × 1/N（硬隔离） |
| TRN-009/010 CU 共享等分 2/4 实例 | vDCU 仅显存隔离、算力共享 | 单实例吞吐 ≈ stream 组（无明显差异，需验证） |

**核心指标**：并发态单实例吞吐（samples/s）；保持率 = 并发单实例吞吐 / 同形态单实例吞吐；总吞吐 = Σ 各实例吞吐。
**判据**：stream 组 vs CU 共享四等分组单实例吞吐差异 ≤ 10%（按建强文档结论"没啥差异"）；CU 独立等分组显著低于 stream 组（体现算力硬隔离）。

## 4. 用例设计（升级 TRN-006～010）

统一执行纪律（所有多实例场景）：
1. 按场景创建 vDCU / 准备整卡环境；
2. **同步拉起 N 个相同实例**（N=2 或 4），确认全部进入训练循环（各实例日志出现首个 step 输出）；
3. 全部运行后统一开始计时，记录各实例 epoch 耗时与吞吐；
4. 训练结束后汇总：单实例吞吐、保持率、总吞吐、与整卡单实例基线的比值。

**TRN-006U 整卡多实例（stream 基线）**：整卡起 2 实例与 4 实例各一组；预期各实例吞吐接近整卡单实例（多 stream 争抢程度量化）。
**TRN-007U/008U 等分多实例（vDCU 硬隔离）**：二等分 2 实例、四等分 4 实例；预期单实例吞吐随等分比例下降（四等分约为基线 1/4），验证 CU 隔离生效。
**TRN-009U/010U CU 共享等分多实例**：CU 共享二等分 2 实例、CU 共享四等分 4 实例；预期单实例吞吐与 TRN-006U 同并发度下无明显差异（建强文档结论）。
**TRN-CMP 结论对比**：将 stream 组与 CU 共享四等分组并排对比，输出差异百分比与结论（"无明显差异"或"存在差异点及原因分析"）。

## 5. 结果输出要求

- 每组场景输出：各实例吞吐明细表、并发态总吞吐、保持率、与整卡单实例基线比值；
- 最终结论一句话："整卡多 stream 与 CU 共享四等分 vDCU 的并发单实例性能差异为 X%（≤10% 判定无明显差异），CU 独立等分体现算力硬隔离"；
- 若差异超阈值：定位差异来源（显存带宽争抢、CU 调度策略、vDCU 切分开销）并记录。

## 6. HAMi 模式部署要求（引用《HCU Device Plugin-v3.0.1》）

今后使用 HAMi 模式必须按以下官方文档步骤部署（受限用例恢复执行的先决条件）：

1. **节点标签**：`kubectl label nodes <node-name> hcu=on`（5.1.1；vHCU 动态切分模式为 `dcu=on`，4.3.1）；
2. **插件部署**：HAMi 模式 HCU-Device-Plugin（`k8s-dcu-plugin-hami.yaml`，部署前需安装 cert-manager）；HAMi 调度器按 HAMi 官方文档部署；
3. **资源申请**：`hygon.com/hcunum`（数量）+ `hygon.com/hcucores`（算力 %）+ `hygon.com/hcumem`（显存 MB）；仅指定显存即 CU 共享切分（驱动 6.3.16+ 支持）；
4. **使用限制**（部署验证必须检查）：每个容器最多申请 **1 张 vHCU**；**不支持 initContainers 申请**；
5. **资源名差异注意**：官方文档 5.1 为 `hygon.com/hcunum`，4.3 为 `hygon.com/dcunum`；本环境实测（dcu-device-plugin v2.4.2，RESOURCE_REGISTER_STRATEGY=hami）注册 `hygon.com/dcunum`——执行前以 `kubectl describe node` 实际 allocatable 为准，自动化已支持两种资源名自动识别；
6. **验证**：节点 allocatable 注册 hcunum/dcunum、hcucores、hcumem 三类资源后方可执行 HAMI/K8S/VOL 用例。

## 7. 自动化脚本改造建议

现行自动化（[workload.py](cases/workload.py)）只有 TRN-005（二等分双容器并发训练），缺少 stream vs vDCU 的完整对比组。改造点：

1. 新增 `trn_006u~010u`：整卡 2/4 实例、等分 2/4 实例、CU 共享 2/4 实例，共 5 组；
2. 同步拉起：全部实例 `detach=True` 启动后，统一轮询各容器日志出现首个 step 再开始计时（避免串行启动造成测量窗口不一致）；
3. 采集并发态吞吐：复用 [bert_smoke.py](assets/bert_smoke.py) 的 `SMOKE_RESULT` 输出（含 throughput/acc），每实例单独记录；
4. 结论对比在用例内计算：stream 组 vs CU 共享组差异百分比直接进断言（≤10%）；
5. HAMi 资源名识别已由 [cluster.py](cases/cluster.py) `_resource_mode()` 支持（dcunum/dcu 两种），补 hcunum 识别后即可覆盖官方文档 5.1 场景。
