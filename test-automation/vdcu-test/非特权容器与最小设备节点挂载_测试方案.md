# 「非特权容器与最小设备节点挂载」测试方案（总结版）

依据：《vDCU 容器挂载测试》（原始 4 场景）、《vDCU 虚拟化测试方案_v1.2_20261102》（CTR-009、SEC-001/002、3.1 挂载要素、附录 A.2）及组长对最小设备节点挂载的新要求（2026-11 会议纪要）。

## 1. 需求要点（对话提炼）

1. **交付形态以 Kubernetes 为主**：单机 Docker 容器测试的挂载方式应与 K8S 设备插件实际注入方式对齐——最终容器里只注入单卡（或指定几张卡）的设备符，不会把整机所有卡的设备符都挂进来。
2. **容器挂载分两种形态，不必纠结"非特权"这个说法**：
   - 形态 A 特权容器：`--privileged`；
   - 形态 B 最小设备节点挂载：不加 `--privileged`，只透传必需的最小设备节点。
3. **KFD 与 MKFD 为透传必挂节点**：只要透传 DCU 卡（整卡或 vDCU），`/dev/kfd`、`/dev/mkfd` 两种形态都必须挂载。
4. **最小化要求升级：不再挂整棵 `/dev/dri`**。当前脚本 `--device=/dev/dri` 会把全部卡的 card/render 设备符都注入容器；新要求改为**只透传被测试 vDCU 所在物理卡对应的 `cardN` 与 `renderDN` 两个设备符**。
5. **设备符与物理卡的映射关系**：一般规律为 PCIe 索引对应 `card(物理卡号+1)`、`renderD(128+物理卡号)`，即 DCU 0 → card1 / renderD128，DCU 5 → card6 / renderD133。以现场 `lspci` 与 `/dev/dri` 实际符号为准校准。
6. **vDCU 配置同样最小化**：只挂被测试 vDCU 自己的配置文件（如 `vdev0.conf`），不挂整个 `/etc/vdev` 目录。
7. **回归风险**：驱动 6.3.8 之前，"只挂 vDCU 所在物理卡的 card/render 设备符"存在 bug，当前驱动（6.4.2-V2.1.0）上必须显式回归验证。

## 2. 最小挂载清单

| 项目 | 整树挂载（现状） | 最小设备节点挂载（新要求） |
| --- | --- | --- |
| 计算设备 | `--device=/dev/kfd` | `--device=/dev/kfd`（必挂） |
| 管理设备 | `--device=/dev/mkfd` | `--device=/dev/mkfd`（必挂） |
| DRI 节点 | `--device=/dev/dri`（整树，所有卡可见） | `--device=/dev/dri/cardN --device=/dev/dri/renderDN`（仅 vDCU 所在物理卡） |
| vDCU 配置 | 按 vdev 逐个挂载 | 只挂被测 vDCU 的 `vdevN.conf`（保持原文件名，见 v1.2 3.1 改名教训） |
| 运行时库 | `-v /opt/hyhal:/opt/hyhal:ro` | 同左 |
| 特权 | 不使用 `--privileged` | 不使用 `--privileged` |

标准命令模板（以 vDCU0 位于物理卡 5 为例，card/render 按第 3 节校准后代入）：

```bash
docker run -it --rm \
  --device=/dev/kfd --device=/dev/mkfd \
  --device=/dev/dri/card6 --device=/dev/dri/renderD133 \
  -v /etc/vdev/vdev0.conf:/etc/vdev/docker/vdev0.conf:ro \
  -v /opt/hyhal:/opt/hyhal:ro \
  bert:v1 bash
```

## 3. 设备节点映射与现场校准（前置）

映射规则（一般规律，不写死）：**物理卡 P → card(P+1)、renderD(128+P)**。

校准步骤（每台被测机执行一次，作为用例前置）：
1. `hy-smi virtual --show-device-info` 记录物理卡号及 PCIe 信息；
2. `ls -l /dev/dri/ /dev/dri/by-path/` 确认 cardN、renderDN 与 PCIe 地址的对应关系；
3. 三对照（物理卡号 ↔ PCIe ↔ card/render 编号）不一致时，以实际符号为准并在报告中记录本机映射表。

## 4. 测试用例设计

用例沿用 v1.2 方案编号扩展，建议在 CTR 章新增 009B～009E，并改造 SEC-001/002。

### 4.1 前置用例

**P0-1 设备节点映射校准**：执行第 3 节步骤，产出本机「物理卡号 → cardN/renderDN」映射表，写入报告环境信息。

### 4.2 正向用例（核心新增）

**CTR-009B 非特权 + 单卡最小设备节点挂载基础可用**
1. 在卡 A 创建 1 个 vDCU（如 vdev0）；
2. 按第 2 节模板启动容器（仅 kfd/mkfd + vDCU 所在卡的 cardN/renderDN + vdev0.conf），无 `--privileged`；
3. 容器内执行 `hy-smi virtual --show-device-info`、`torch.cuda.device_count()` 与最小 HIP 样例（矩阵乘）；
4. 预期：设备数 1，CU/显存与配额一致，HIP 运算正常。

**CTR-009C 跨卡多 vDCU 最小挂载**：vDCU 分属两物理卡时挂两对 card/render；预期两设备可见、显存配额独立（通信结论另按 COM 章）。

**CTR-009D 只挂关联 vDCU 配置**：仅挂 vdev0.conf（不挂 `/etc/vdev` 整目录）；预期容器内只见 1 个设备、配额正确，且读不到其他 vDCU 配置。

### 4.3 负向用例

**CTR-009E 必挂节点缺失行为**：
1. 缺 `/dev/mkfd` 启动并运行 HIP 样例，记录失败现象；
2. 缺 cardN/renderDN（只挂 kfd/mkfd）启动，记录失败现象；
3. 预期：功能不可用且失败现象明确、可复现，写入附录 ISSUE 备查。

### 4.4 安全用例（改造 v1.2 SEC-001/002）

**SEC-001 设备节点最小权限挂载（改造）**：最小挂载启动后检查容器内 `/dev/dri` 仅含注入的 cardN/renderDN；`ls /dev` 无其他 DCU 设备符；`mknod` 创建新设备节点被拒绝。

**SEC-002 越权访问其他 vDCU 设备（改造）**：容器内尝试打开未注入的其他 card 设备、读取其他 vdev 配置、执行 `hy-smi virtual --destroy-vdevices`；预期全部被拒绝。

### 4.5 对照与回归用例

**CTR-009A 形态对照**（保留 v1.2 CTR-009 原步骤）：同一业务分别在 `--privileged` + 整树 `/dev/dri`、非特权 + 最小节点两种形态下运行，功能结果应一致。

**CTR-009F 历史缺陷回归（6.3.8 之前 bug）**：在当前驱动（6.4.2-V2.1.0）上，仅挂 vDCU 所在物理卡 card/render 的最小形态下完整执行 CTR-009B/C/D；记录驱动版本与结果，若复现 bug 记录 ISSUE 并说明规避方式（临时回退整树 /dev/dri）。

### 4.6 K8S 对齐用例

**K8S-002 增强**：设备插件（hygon.com/dcu / vHCU）注入的 Pod 内执行 `ls -l /dev/dri`，确认注入视图与单机最小挂载一致（仅单卡 card/render，非整树）；资源回收检查不变。

## 5. 结果判据

- CTR/TRN/INF 冒烟在最小挂载形态下全部 PASS；
- 容器内 `/dev/dri` 仅含指定卡的 cardN/renderDN，其他卡设备符不可见；
- mknod 与越权访问被拒绝；
- 缺 kfd/mkfd/card/render 任一项时失败现象明确；
- 特权形态与最小形态功能无差异；
- 当前驱动上无 6.3.8 之前 bug 复发，或有复发记录与规避方案。

## 6. 自动化脚本改造建议

现行实现位于 `vdcu/core.py` 的 `Context.docker()`（[core.py:186-209](vdcu/core.py#L186-L209)），当前固定挂 `--device=/dev/dri` 整树。改造点：

1. `--device=/dev/dri` 改为按 vDCU 所在物理卡透传 `card(P+1)`、`renderD(128+P)`；
2. 映射公式做成配置项（如 `card_render_offset`），现场校准后可覆盖；
3. 物理卡来源直接复用 `vdevs()` 已解析的 `phys` 字段；
4. 保留「整树 /dev/dri」作为对照形态开关（用于 CTR-009A）；
5. 容器内探针（`ctr.py` 的 PROBE）增加 `ls -l /dev/dri` 输出，供 SEC-001/CTR-009B 断言。

## 7. 风险与注意事项

- **映射不写死**：card/render 编号随机型、PCIe 拓扑可能变化，必须先校准后执行；
- **vdevN.conf 文件名**：v1.2 方案 3.1 已实测「改名挂载导致容器内 No CUDA GPUs are available」，必须按原始文件名挂载；
- **containerd 对齐**：`ctr run --device` 同样按单卡 card/render 注入，与 Docker 形态结果一致；
- **6.3.8 历史 bug**：回归结果与驱动版本必须一并记录在报告中。
